## Context

Проект использует npm для управления зависимостями. Bun уже установлен в системе и доступен в PATH. Проект — фронтенд на Svelte с Vite.

## Goals / Non-Goals

**Goals:**

- Заменить npm на bun как пакетный менеджер
- Обеспечить воспроизводимую установку зависимостей через `bun.lock`
- Сохранить совместимость с существующими скриптами сборки

**Non-Goals:**

- Миграция на bun как runtime для JavaScript (проект остаётся на Node.js для Vite)
- Изменение архитектуры приложения
- Обновление зависимостей до последних версий (отдельная задача)

## Decisions

### Использовать bun install вместо npm install

**Причина**: Bun выполняет установку зависимостей быстрее npm за счёт параллельной загрузки и кеширования.

**Альтернативы**:

- Оставить npm — не решает проблему скорости
- Использовать pnpm — thêm ещё один инструмент, bun уже доступен

### Удалить package-lock.json, перейти на bun.lock

**Причина**: bun.lock — нативный формат блокировки для bun. Хранение двух lock-файлов создаёт путаницу.

**Риск**: Разработчики, не использующие bun, не смогут установить зависимости. Решение: документировать требование bun в README.

### Сохранить скрипты в package.json без изменений

**Причина**: `bun run` совместим с форматом скриптов npm. Изменения не требуются.

## Risks / Trade-offs

- **Совместимость**: Разработчики с npm не смогут использовать проект без установки bun. Mitigation: документация в README.
- **CI/CD**: Если CI использует npm, нужно обновить конфигурацию. Mitigation: проверить и обновить при необходимости.
